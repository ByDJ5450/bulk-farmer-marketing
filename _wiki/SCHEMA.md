# 벌크농부 마케팅 위키 — 스키마

> 이 파일은 위키의 **규칙서**다. 카파시 LLM Wiki 패턴
> (gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)을 벌크농부에 맞게 적용했다.
> 클로드 코드 세션이 위키를 만지기 전에 반드시 이 파일을 읽는다.

## 3계층 구조

| 계층 | 위치 | 규칙 |
|---|---|---|
| **원본 (Raw)** | `_analytics/` `_testimonials/` `_threads/` `_cardnews/` 등 기존 산출물 폴더 | 위키는 **읽기만** 한다. 절대 수정하지 않는다 |
| **위키 (Wiki)** | `_wiki/*.md` | LLM이 작성·유지. 사람은 옵시디언으로 열람·승인 |
| **스키마 (Schema)** | 이 파일 + `CLAUDE.md` | 구조와 규칙. 사람만 바꾼다 |

## 페이지 규칙

1. **원본만 인용한다.** 위키 페이지끼리 근거로 인용하지 않는다 (자기참조 오염 방지).
   연결은 `[[위키링크]]`로 하되, **근거**는 반드시 원본 파일 경로 + 날짜로 단다.
2. 모든 페이지 상단에 YAML 프론트매터: `type` (insight / entity / bank / index), `updated`, `sources`.
3. 판단이 뒤집힌 학습은 지우지 않고 ~~취소선~~ + 뒤집힌 날짜·근거를 남긴다.
   (예: "영어 롱폼 지양" → 2026-07-31 중복 집계 오류로 폐기)
4. 파일명은 한글, 하이픈 구분: `검증된-인사이트.md`, `수강생-성훈.md`.
5. CLAUDE.md·memory에 이미 있는 운영 규칙(서버, launchd, 자격증명)은 **위키에 복제하지 않는다.**
   위키는 마케팅 지식(인사이트·고객·소재·후기) 전용이다.

## 운영 3동작

### Ingest — 새 자료가 들어올 때
주간 리포트 도착, 후기 접수, 실측 발견 시:
1. 원본을 읽고 관련 위키 페이지를 갱신 (보통 1~3장)
2. `index.md`에 새 페이지 등록, `log.md`에 한 줄 기록
3. 판단 변경이 있으면 `검증된-인사이트.md`에 날짜와 근거를 단다

### Query — 콘텐츠 기획할 때
스레드·릴스·카드뉴스 기획 전에 `검증된-인사이트.md` + `소재은행.md`를 먼저 읽는다.
좋은 기획 결론이 나오면 소재은행에 축적한다 (파생하고 버리지 않는다).

### Lint — 월요일 주간 리포트 후
- 페이지 간 모순 확인 (인사이트 vs 최신 리포트)
- 고아 페이지(어디서도 링크 안 된 페이지) 확인
- 재검증 필요 표시(⚠️)가 해소됐는지 확인

## 옵시디언 사용법 (사람용)

- 이 폴더(`00_벌크농부 마케팅 에이전트팀`)를 통째로 Vault로 연다 → 위키 + 원본을 한 그래프에서 봄
- Graph View로 소재-인사이트-수강생 연결 확인, 고아 페이지 발견
- Web Clipper로 레퍼런스 아티클을 `_org/inbox/`에 저장 → 다음 세션이 Ingest
- `.obsidian/`은 git에 올리지 않는다 (.gitignore 처리됨)
