스레드 초안 8개를 생성한다. 이 중 3~5개가 승인돼 발행된다. 대화 상대는 없다. 질문하지 말고 끝까지 수행한다.

## 절차

1. `_context/threads_agent.md`, `_template/threads_template.md`, `_context/brand_guidelines.md`를 읽는다.

2. 발행 이력 대조 — 아래 두 곳을 모두 읽는다.
   - `_threads/published.md` (자동 발행 이력)
   - 발행 이력 메모리 (2026-05-04 5건, 2026-05-11 1건의 소재·훅 구조)

   **같은 주제를 다시 써도 된다. 단, 각색해야 한다.**
   하루 3~5개씩 나가므로 소재를 완전히 배제하면 금방 고갈된다.
   좋은 주제는 각도를 바꿔 다시 쓰는 편이 억지 소재를 짜내는 것보다 낫다.

   각색으로 인정되는 것 — 아래 중 **최소 두 가지**가 달라야 한다.
   - 형식 (유형 1 스토리 ↔ 2 정보 ↔ 3 질문)
   - 진입 각도 (본인 경험 ↔ 수강생 사례 ↔ 흔한 오해 반박 ↔ 숫자 제시)
   - 첫 문장 훅
   - 결론에서 남기는 행동

   각색이 아닌 것 — 이건 배제한다.
   - 문장만 바꾸고 훅·전개·결론이 같은 글
   - 같은 수치를 같은 순서로 나열한 글

   `summary` 필드에 **"[재구성] 원래 소재 → 이번 각도"** 형태로 남긴다.
   예: `[재구성] 유산소 오해 → 이번엔 수강생 사례로 진입, 결론은 주 2회 유지`

3. 조합 결정 — 8개가 서로 겹치지 않게 분산한다.
   형식: 유형 1(스토리) / 2(정보) / 3(질문)
   주제: A(오해) B(제한된 믿음) C(실수) D(노하우) E(장애물) F(사회적 증거)
   같은 형식×주제 조합을 8개 안에서 두 번 쓰지 않는다.
   주제 A~F 중 최소 5개가 등장하게 한다 — 한 주제에 몰리면 계정이 단조로워진다.
   아직 안 쓴 조합을 먼저 채우고, 남는 자리는 2번의 각색 규칙으로 채운다.

4. 초안 작성 → 아래 신뢰 검증 통과 → JSON 저장 → 텔레그램 발송

## 신뢰 검증 (가장 중요 — 통과 못 하면 그 초안은 버린다)

이 계정은 브랜드다. 틀린 정보 하나가 쌓아온 신뢰를 깎는다.
**애매하면 쓰지 않는다.** 8개를 채우는 것보다 6개가 정확한 게 낫다.
버린 초안은 개수를 맞추려고 억지로 메우지 않는다.

### 절대 금지

**① 지어낸 수치·연구·출처**
- "연구에 따르면", "논문에서", "전문가들은" — 실제 출처를 댈 수 없으면 쓰지 않는다
- "근육량 30% 증가", "성공률 80%" 같은 통계 — 근거 없는 숫자 금지
- 확인되지 않은 제3자 사례를 사실처럼 쓰지 않는다

**② 피트니스 사실 오류 3종**
- "운동 후 30분 이내 단백질" → "1~2시간 이내" 또는 "하루 총량 기준"
- "벌크업의 X%는 식단" → "운동(자극) + 식단(재료), 둘 다 필수"
- 벌크업 맥락에서 "칼로리를 줄이고" → "칼로리 잉여를 유지하면서"

**③ 결과 보장·과장**
- "무조건", "100%", "누구나", "반드시 성공" 금지
- "○kg 보장", "○개월이면 완성" 금지
- 수강생 사례 인용 시 "개인에 따라 결과가 다를 수 있습니다" 고지

**④ 의료·건강 주장**
- 질병 치료·예방 효과 암시 금지
- 보조제 효능 단정 금지

### 반드시 지킬 것

**본인 경험과 일반화를 구분한다.**
- (O) "저는 3개월 동안 이렇게 했더니 이랬습니다"
- (X) "3개월이면 이렇게 됩니다"

**검증 가능한 사실만 트레이너 이력으로 쓴다.**
- 확정 사실: 181cm, 55kg → 88kg, K-Classic 클래식 보디빌딩 3위
- 이 외의 수치·경력을 새로 만들어내지 않는다

**숫자를 쓸 때는 출처를 자기 경험으로 한정하거나, 원리로 설명한다.**
- (O) "체중 1kg당 단백질 1.6g 정도를 기준으로 잡습니다"  ← 통용되는 실무 기준
- (X) "연구 결과 1.6g이 최적으로 밝혀졌습니다"          ← 출처 못 대면 금지

### 각 초안마다 자기 검증 기록

JSON의 `fact_check` 필드에 아래를 남긴다.
- `claims`: 사실 주장이 들어간 문장 목록 (없으면 빈 배열)
- `basis`: 각 주장의 근거 — "본인 경험" / "통용 기준" / "확정 이력" 중 하나
- 근거를 셋 중 하나로 댈 수 없는 주장이 있으면 **그 초안을 버리고 다시 쓴다**

## 말투 규칙

- 짧은 문장, 줄바꿈 충분히
- 경어체 (합니다/입니다)
- 수치는 직접 언급
- 이모지 최소 (행동 촉구 시 1개까지)
- "안녕하세요" 또는 브랜드 소개로 시작 금지
- 해시태그 1~2개 이내
- 계정 표기는 `@bulk_farmer` (한글 금지)

## 저장

`_threads/pending/{오늘날짜}.json`

```json
{
  "date": "YYYY-MM-DD",
  "total": 8,
  "drafts": [
    {
      "index": 1,
      "type": "유형 1 (스토리)",
      "topic": "B (제한된 믿음)",
      "summary": "한 줄 요약 — 발행 이력 기록용",
      "text": "실제 발행될 본문 전체",
      "fact_check": {"claims": ["..."], "basis": ["본인 경험"]},
      "status": "pending"
    }
  ]
}
```

`status`는 반드시 `pending`으로 둔다. 발행은 워커가 한다.

## 텔레그램 발송

자격증명은 `~/.config/bulkfarmer/telegram.env`. **토큰 값을 출력에 찍지 않는다.**

먼저 요약 1건:
```
📝 오늘의 스레드 초안 N개
3~5개 승인해주세요. 승인하면 100분 간격으로 하나씩 자동 발행됩니다.
```

그다음 초안마다 1건씩, 인라인 버튼을 붙여 보낸다.

```bash
source ~/.config/bulkfarmer/telegram.env
curl -s -X POST "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/sendMessage" \
  -H "Content-Type: application/json" \
  -d '{
    "chat_id": CHAT_ID,
    "text": "1/8  유형 1 · B(제한된 믿음)\n\n<본문>",
    "reply_markup": {"inline_keyboard": [[
      {"text":"✅ 발행 예약","callback_data":"pub:YYYY-MM-DD:1"},
      {"text":"🗑 버림","callback_data":"del:YYYY-MM-DD:1"}
    ]]}
  }'
```

`callback_data`는 반드시 `pub:{날짜}:{index}` / `del:{날짜}:{index}` 형식이어야 한다.
워커가 이 형식으로만 파싱한다.

승인은 **즉시 발행이 아니라 예약**이다. 워커가 08~23시 사이에 100분 간격으로
한 건씩 내보낸다. 한꺼번에 눌러도 글이 뭉쳐 나가지 않는다.

버려진 초안이 있으면 마지막에 알린다: "검증에서 N개를 버렸습니다 — 사유: ..."
