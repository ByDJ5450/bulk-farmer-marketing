# 네이버 블로그 발행

## 자동 발행은 불가능하다

네이버 **블로그 글쓰기 API는 2020-05-06 종료**됐다.
광고성 글 대량 발행이 이유였고, 서비스 10년 만에 닫혔다.

개발자센터 `사용 API` 드롭다운에 **블로그 항목 자체가 없다.** 목록이 잘린 게 아니다.
앱 등록·OAuth·토큰 — 전부 필요 없다.

> 2026-08-02 확인. 근거: [뉴스핌 2020-04-13](https://www.newspim.com/news/view/20200413000737)
> `naver-openapi-guide` 문서에는 아직 writePost가 남아 있지만 **종료 전 아카이브**다.
> 그 문서를 근거로 판단하지 않는다.

브라우저 자동화(셀레니움 등)로 우회하는 방법이 있지만 **쓰지 않는다.**
네이버가 API를 닫은 이유가 정확히 그 행위이고, 계정 제재 대상이다.
검색 유입을 노리고 블로그를 하는데 계정이 날아가면 본말전도다.

## 그래서 이렇게 한다 — 붙여넣기 1회

```bash
/usr/bin/python3 _blog/to_clipboard.py _blog/{글폴더} --notify
```

본문이 **서식 그대로**(제목·표·굵기 유지) 맥 클립보드에 올라간다.
`blog.naver.com` 글쓰기 열고 본문 칸에 `Cmd+V` 하면 끝이다.

`--notify`를 붙이면 텔레그램으로 제목과 안내가 간다. 폰으로 확인하고 맥에서 붙여넣는 흐름이다.

발행 전 직접 확인할 것: **카테고리 / 태그 / 공개설정**

주 1개 기준으로 실제 손이 가는 시간은 2분 내외다.

## 글 폴더 구조

```
_blog/{slug}/
  title.txt      제목 한 줄
  content.html   본문 HTML (사진 자리표시자 포함)
  tags.txt       태그 목록 (줄바꿈 구분)
  images/        본문에 넣을 사진 — 파일명 앞 번호가 삽입 순서
```

## 검색 노출 체크리스트 (작성 시 매번 대조)

네이버는 C-Rank(블로그 신뢰도)와 D.I.A.+(문서 품질)로 순위를 매긴다.
2026년 D.I.A.+는 하이퍼클로바X 기반이라 키워드 매칭이 아니라 **문서 맥락과 정보 충실도**를 본다.
따라서 아래는 최소 조건이고, 결국 내용이 실제로 도움이 돼야 한다.

| 항목 | 기준 | 이유 |
|------|------|------|
| 제목 길이 | **30~40자** | 모바일 검색결과에서 약 35자까지만 보인다 |
| 제목 키워드 위치 | **맨 앞** | 뒤로 밀리면 잘려서 안 보인다 |
| 본문 길이 | **2,000~3,000자** (최소 1,500) | 경쟁 키워드 기준 평균 |
| 주 키워드 반복 | **3~5회** (제목 1 + 첫 문단 1 + 본문 2~3) | 10회 넘으면 스터핑으로 감점 |
| 첫 문단 | 주 키워드 포함 + 후킹 | 이탈하면 체류시간이 죽는다 |
| 소제목 | `<h3>`로 6~8개, 연관 키워드 포함 | 스마트블록이 세부 의도별로 잡아간다 |
| 사진 | **6장 이상**, 가로 1,200px, 500KB 이내 | 직접 촬영본에 가점. 영상 프레임도 직접 촬영본이다 |
| 태그 | 8~10개 | 주 키워드 변형 위주 |
| 발행 주기 | 주 1~2회 꾸준히 | C-Rank는 주제 일관성과 활동성을 본다 |

### 모바일 가독성 (이게 체류시간을 좌우한다)

블로그 독자의 대부분은 폰으로 본다. 모바일 본문 한 줄은 **한글 20자 남짓**이다.
20자를 넘으면 문장이 아무 데서나 잘려 다음 줄로 넘어가고, 그게 쌓이면 글자 벽이 된다.

| 규칙 | 기준 |
|------|------|
| 한 줄 | **20자 내외**, 25자 넘기지 않는다 |
| 줄바꿈 | 의미 단위로 `<br />` — 문장이 저절로 꺾이게 두지 않는다 |
| 한 문단 | 1~3줄. 넘으면 `<p>`를 나눈다 |
| 문단 사이 | 반드시 빈 줄 |
| 긴 문장 | 두 문장으로 쪼갠다. 접속사로 잇지 않는다 |

검증:
```bash
/usr/bin/python3 - <<'EOF'
import re, html; from pathlib import Path
t = Path('_blog/{slug}/content.html').read_text(encoding='utf-8')
plain = html.unescape(re.sub(r'<[^>]+>','', re.sub(r'<br\s*/?>|</p>|</h3>|</li>|</blockquote>','\n',t)))
lines = [l.strip() for l in plain.split('\n') if l.strip() and not l.strip().startswith('■')]
print(f"평균 {sum(map(len,lines))//len(lines)}자 | 25자 초과 {sum(1 for l in lines if len(l)>25)}개 / {len(lines)}개")
EOF
```

### 발행 전 모바일 프리뷰

붙여넣기 전에 **실제로 어떻게 보이는지 눈으로 확인한다.** 390px 폭으로 렌더링해
스크린샷을 찍으면 네이버 모바일 화면과 거의 같다. 만드는 코드는
`_blog/12week_case_2026-08-02/_preview.html` 를 그대로 복사해 쓴다.

**체류시간이 실질적으로 가장 중요하다.** 2026년 기준 상위권은 평균 2분 30초 이상이다.
표·목록·사진을 섞어 스크롤이 끊기지 않게 만든다. 글자 벽을 만들지 않는다.

### 사진 자리표시자

본문에 이렇게 넣어두고, 붙여넣은 뒤 그 줄을 지우고 사진을 삽입한다.

```html
<p>■ 사진 3 — <strong>3_줄자측정.jpg</strong> (이 줄을 지우고 사진을 넣으세요)</p>
```

**발행 전 `■`가 본문에 남아 있지 않은지 반드시 확인한다.**

## HTML 작성 규칙

스마트에디터가 붙여넣기를 재해석하므로 태그를 단순하게 쓴다.

| 쓸 것 | 용도 |
|-------|------|
| `<p>` `<br />` | 문단·줄바꿈 |
| `<h3>` | 소제목 |
| `<strong>` | 강조 |
| `<blockquote>` | 인용 |
| `<table border="1" cellpadding="8">` | 수치 비교표 |
| `<ul><li>` | 목록 |

`<div>` 레이아웃, 인라인 `style`, 외부 이미지는 쓰지 않는다 — 붙여넣을 때 깨진다.
사진은 붙여넣기 후 에디터에서 직접 올린다.

## 왜 블로그를 유지하는가

다른 채널은 전부 알고리즘 노출이라 발행 순간이 지나면 죽는다.
블로그는 "마른 체형 벌크업", "체중 안 느는 이유" 같은 검색어로 몇 달 뒤에도 들어온다.
현재 유입이 100% 알고리즘 의존이고 검색 자산이 하나도 없다. 주 1개면 충분하다.
