# Meta API 연동 — 설정 안내서

> 목적: 인스타그램·스레드 데이터를 자동 수집하고, 이후 자동 발행까지 확장한다.
> 작성 2026-08-01 · 갱신 2026-08-02 · 상태: **1·2단계 완료, 3단계 검증 중**

---

## 이 앱 하나로 얻는 것

```
Meta 개발자 앱 1개
  ├─ 스레드 인사이트 조회      ← 1단계
  ├─ 인스타그램 인사이트 조회   ← 2단계
  ├─ 스레드 발행               ← 3단계 (텍스트, 쉬움)
  └─ 인스타그램 발행           ← 4단계 (이미지 호스팅 필요)
```

설정은 한 번, 기능은 넷. 단계별로 검증하며 올라간다.

---

## 진행 원칙

**읽기부터 한다.** 조회가 되면 앱·토큰·권한이 제대로 잡혔다는 뜻이고, 발행이 실패해도 원인을 좁힐 수 있다. 발행부터 시도하면 뭐가 문제인지 알 수 없다.

**본인 계정만 다룬다.** 남의 계정 데이터를 읽거나 앱을 공개 배포하지 않으므로, **개발 모드에서 앱 심사 없이** 진행할 수 있을 것으로 본다. 다만 발행 권한(`threads_content_publish` 등)은 조회 권한보다 조건이 까다로울 수 있어 진행하며 확인한다.

**메뉴 이름이 다를 수 있다.** Meta 개발자 콘솔은 자주 바뀐다. 아래 단계와 화면이 다르면 **캡처를 주시면 같이 풉니다.** 문서를 그대로 믿고 헤매지 마세요.

## 사전 조건

- [ ] 인스타그램 계정이 **프로페셔널(비즈니스 또는 크리에이터)** 인가?
      → 인스타 앱 → 설정 → 계정 유형 및 도구에서 확인. 개인 계정이면 전환 필요(무료, 몇 번 탭)
- [ ] 스레드 계정이 해당 인스타 계정과 연결되어 있는가? (보통 자동 연결됨)
- [ ] Meta 개발자 계정 (developers.facebook.com, 무료)

---

## 1단계 — 스레드 인사이트 조회

가장 쉽고 안전한 첫 관문. 여기가 되면 나머지는 같은 패턴이다.

```
1. developers.facebook.com → 내 앱 → 앱 만들기
2. 사용 사례에서 Threads 관련 항목 선택
3. 앱 생성 후 → Threads API 설정
4. 권한 추가: threads_basic, threads_manage_insights
5. 본인 계정을 앱의 테스트/개발 사용자로 등록
6. 액세스 토큰 생성 → 장기 토큰(약 60일)으로 교환
7. 토큰을 ~/.config/bulkfarmer/meta.env 에 저장 (저장소 밖, 권한 600)
```

**검증:** 본인 스레드 게시물 목록과 조회수가 나오면 성공.

## 2단계 — 인스타그램 인사이트 조회

두 갈래가 있다. **위쪽을 권장한다.**

| 방식 | 필요 조건 | 비고 |
|------|----------|------|
| **Instagram API with Instagram Login** | IG 프로페셔널 계정만 | 페이스북 페이지 불필요 — 1인 운영에 적합 |
| Instagram API with Facebook Login | IG + 페이스북 페이지 연결 | 페이지를 새로 만들어야 할 수 있음 |

```
1. 같은 앱에 Instagram 사용 사례 추가
2. 권한: instagram_basic 계열 + insights 계열
   (지표 이름과 권한 이름이 API 버전마다 다름 — 콘솔에 표시되는 현재 값을 따른다)
3. 토큰 발급 → meta.env 에 추가
```

**주의:** Meta가 `impressions` 등 일부 지표를 정리·폐기해왔다. 어떤 지표를 쓸 수 있는지는
**연동 시점의 콘솔·문서에서 확인**한다. 제 기억으로 코드를 쓰면 틀린다.

**검증:** 최근 게시물의 도달·저장·공유가 나오면 성공.

## 3단계 — 스레드 발행 (승인 게이트)

```
매일  스레드 작가가 초안 5개 생성 → 텔레그램으로 전송
      ↓
사용자  탭으로 승인 / 수정 / 버림          ← 여기만 사람
      ↓
자동   승인분만 발행 → 발행 이력 자동 기록
```

**완전 자동은 하지 않는다.** 사실 오류 3종·과장 표현 규칙이 걸려 있어 사람 눈을 거치지 않고
나가면 되돌릴 수 없다. 몇 주 돌려 어긋남이 없으면 그때 자동 발행을 검토한다.

**맥 전원 문제:** 맥을 쓸 때만 켜신다고 하셨으므로 **정시 분산 발행은 로컬로 불가능**하다.
승인 시점에 발행하거나, 상시 실행 워커(Cloudflare Workers 등)를 두는 선택이 필요하다.
이 결정은 3단계 진입 시점에 다시 논의한다.

---

## 4단계 — 인스타그램 발행 (카드뉴스 캐러셀)

```
① 카피·HTML 생성        ✅ 완료 (카드뉴스 디렉터)
② HTML → PNG 렌더링     ✅ 완료 (크롬 헤드리스, 1080×1350)
③ 이미지 공개 URL 호스팅  ⬜ 필요 — Meta가 로컬 파일을 받지 않음
④ 캐러셀 발행 (최대 10장) ⬜ 필요
```

③은 Cloudflare R2 또는 S3 무료 티어로 충분하다. 월 비용 사실상 0원.
캐러셀은 슬라이드마다 미디어 컨테이너를 만든 뒤 하나로 묶어 발행하는 2단계 구조다.

## 공통 유지보수

| 항목 | 내용 |
|------|------|
| **토큰 만료** | 장기 토큰도 약 60일. 갱신 실패 시 **조용히 멈춘다** |
| **대응** | 만료 7일 전 텔레그램 경고 + 갱신 실패 시 즉시 알림 |
| **발행 한도** | 24시간당 상한 있음(수백 건 수준). 하루 5~10개는 문제없음 |
| **비밀 관리** | 토큰은 `~/.config/bulkfarmer/meta.env` (권한 600). **저장소에 넣지 않는다** |

조용히 멈추는 것이 자동화의 가장 큰 위험이다. 알림 장치는 **연동 코드 바깥**에 둔다.
(주간 리포트에서 이미 같은 실수를 한 번 했다 — 실패 알림을 실패하는 대상 안에 넣었다.)
