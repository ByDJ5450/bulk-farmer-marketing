# 릴스·쇼츠 대본 가이드 — 화면과 말이 같이 가게

> 2026-08-05 도입. 릴스·쇼츠 대본은 글이 아니라 설계도다.
> 화면과 음성을 초 단위로 묶어서 쓴다.
> 훅 유형(A~C)·포맷(1~5) 선택은 `_context/shortform_agent.md`가 우선하고,
> 이 문서는 **대본을 어떤 형식으로 쓰는지**를 규정한다.

---

## PART 1. 출력 형식: 초 단위 2열 대본

대본은 반드시 이 형식으로 쓴다. **문단 줄글 금지.**

```
[0:00–0:02] 화면: (정확히 뭐가 보이는지)
            음성: (정확히 뭐라고 말하는지)

[0:02–0:05] 화면: (다음 장면)
            음성: (다음 대사)
```

- 컷마다 타임스탬프. 화면이 바뀌면 대사도 같이 넘어간다
- 대사가 화면 비트보다 길면 화면을 두 컷으로 쪼갠다
- 훅(0:00–0:02)은 **소리를 꺼도 통해야** 한다 — 화면만으로 스크롤이 멈춰야 함
- 이 형식은 `_reels/spec_*.json`(조립 파이프라인 입력)으로 그대로 옮길 수 있어야 한다 —
  컷 경계가 모호한 대본은 스펙으로 못 만든다

## PART 2. 상투 대본 금지 목록

- "오늘은 ~를 보여드릴게요" 금지 — 바로 내용에서 시작
- "자, 그럼 시작해볼까요" 금지 — 죽은 시간
- **스톡 비주얼 묘사 금지** — "노트북 치는 사람", "도시 야경" 같은 아무 영상.
  화면 지시는 **이 대본에서만 나올 수 있는 장면**이어야 함
  (벌크농부 기준: 실제 수업·식단·측정·수강생 촬영본, 롱폼 컷)
- 한 말 다시 요약 금지 — "보셨다시피" 없이 한 번 말하고 넘어가기
- "마무리하자면" 금지 — 마지막 포인트나 CTA로 그냥 끝내기
- 형용사 쌓기 금지 — "미친, 역대급, 인생" 대신 실제로 뭘 하는지
- 문장 길이 균일 금지 — 짧은 펀치 사이에 설명 문장 하나. 말의 리듬 만들기

## PART 3. 플랫폼 감각

- **훅 윈도우**: 처음 1.5초가 시청 지속을 결정. 로고·인트로에 쓰지 말 것
- **컷 전환**: 2~4초마다 화면 변화. 더 길게 가려면 이유가 있어야 함
  (시연, 리액션, 의도된 정적)
- **자막 전제**: 무음 시청 기준으로 쓰기. 한 컷 대사는 한눈에 읽히는 길이 —
  자막이 3줄로 감기면 컷을 쪼갠다
- **CTA 위치**: 팔로우·댓글 요청은 알맹이가 끝난 뒤 **마지막 2~3초.** 중간에 넣지 않기.
  문구는 CLAUDE.md의 쇼츠 CTA 표준(A/B/C) 사용
- **길이**: 아이디어 크기에 맞추기. 포인트 하나면 15~30초.
  숫자 채우려고 늘리지 않기 (릴스 30초 권장·쇼츠 60초 이내는 상한이지 목표가 아니다)

## PART 4. 음성 열 말투 (기존 규칙과 결합)

음성 열은 **소리 내어 읽는 대본**이다. 내레이션 말투 규칙이 그대로 적용된다.

- 비유 금지, 주어·조사 생략 금지
- 호명은 "여러분"
- 수강생 이름은 성훈·재현 (자동 자막이 성우/서우/제현으로 오인식하니 자막 검수 필수)
- 경어체 (합니다/입니다)

## PART 5. 체크리스트

- [ ] 훅이 무음으로도 통하는가
- [ ] 화면 지시마다 대사가 정확히 붙어 있는가 (짝 없는 화면·대사 없음)
- [ ] 상투 대본 금지 목록 위반이 없는가
- [ ] 2~4초마다 화면이 바뀌는가
- [ ] CTA가 마지막 비트에 있는가
- [ ] **음성 열만 따로 소리 내 읽으면 말하는 것처럼 들리는가** (내레이션 티 금지)
- [ ] 화면 지시가 전부 확보 가능한 소스(롱폼 컷·실제 촬영본)인가
